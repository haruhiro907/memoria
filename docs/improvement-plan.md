# Memoria 改善計画（impeccable critique 2026-11-15 の Priority Issues への対応）

前提: impeccable critique の Design Health Score は **23/40（Acceptable）**。指摘は P1×3・P2×2＋細部の非対称 数件。
進め方: バッチ単位で実装 → 都度 tsc / lint / build で検証 → 画面が絡むものはローカル（エミュレータ＋実画面）で確認 → 最後に polish と再 critique でスコア推移を見る。
実施順の考え方: **安全と復旧（P1）→ 供給（写真投入）→ 規律（見た目）→ 細部**。Batch 1 と 2 は独立していて並行可能。

## Phase 0: 前提確認（ローカル、先に済ませる）

- 本番ビルド（`next build`）の CSS が正しく生成されることの確認。サンドボックスの dev サーバーでは Tailwind ユーティリティが生成されず critique の実描画確認ができなかったため、本番側に問題がないことを先に確定させる。
- `npm run test:rules` の実行（Phase 4 の残件検証を兼ねる）。

## Batch 1 — harden: セッションと参加の安全（P1×2）

### 1-1. /join の飾りボタンをなくす
- 対象: `src/components/layout/AppShell.tsx`（JoinGate を含む）、`src/app/(app)/join/page.tsx`
- familyId 未確定の間は、ヘッダーの「ホームへ戻る」をリンクなしのブランド表示に差し替える（押せるのに無反応なボタンを画面に置かない）。
- /join に「いま ○○（メールアドレス）でログインしています」を表示し、ログアウトを明確な副次アクションとして置く（間違ったアカウントでのコード消費を防ぐ）。
- 受け入れ基準: /join 上に「押しても何も起きない主要ボタン」が存在しない。参加中アカウントが画面だけで判別できる。

### 1-2. ログアウトに確認を入れる
- 対象: `src/components/layout/AppShell.tsx`（既存の ConfirmDialog を利用）
- 全ロールでログアウト前に確認ダイアログを挟む。person ロールの文言は「家族の方といっしょのときだけ押してください」とし、誤タップ 1 回でセッションが終わらないようにする。
- 受け入れ基準: 本人が誤タップしても 1 操作ではログアウトしない。家族は従来どおり右上から到達できる。

## Batch 2 — clarify: 復旧フローの記憶依存を解く（P1）

### 2-1. 本人 member にメールアドレスを保持する
- 対象: `functions/src/index.ts`（createPersonAccount）、`src/types/models.ts`（MemberDoc に任意フィールド追加）
- 発行時に member ドキュメントへ本人のメールアドレスを保存する（Functions は発行時に入力を受け取っている）。既存 member（メールなし）は画面側で「未登録」と表示し、移行はしない（次回発行から揃う）。

### 2-2. /settings の復旧 UI を「見て分かる」形に
- 対象: `src/app/(app)/settings/page.tsx`
- メンバー一覧に現在の登録メールを表示する。
- パスワード再設定フォームは登録メールを初期入力し、「このアドレスに再設定メールを送ります」を明示する。
- メール訂正フォームにも訂正対象の現アドレスを表示する。
- 受け入れ基準: 家族が画面の情報だけで復旧作業（再設定・訂正）を完遂できる。記憶に頼る入力欄がない。

### 2-3. 家族自身のパスワード再設定導線
- 対象: `src/app/login/page.tsx`
- ログイン画面に家族向けのパスワード再設定（sendPasswordResetEmail）の導線を追加する（現在は本人の分しかアプリ内にない）。

## Batch 3 — optimize: 写真の一括追加（P2）

- 対象: `src/app/(app)/photos/new/page.tsx`、`src/lib/firestore/photo.ts`（既存の追加処理を再利用）
- ファイル選択に複数選択（multiple）を許可する。複数選択時はキュー表示（サムネイル＋待機／送信中／完了／失敗の状態と n/N の進捗）を出し、順次アップロードする。失敗した写真は理由（平明な文言）＋個別の再試行を持ち、成功分はそのまま入る。
- 1 枚だけ選んだ場合の体験は現行のまま変えない（本人の「選ぶ＝完了」を守る）。
- アップロード中の画面遷移は注意を出す。
- 受け入れ基準: 10 枚を 1 回の選択で投入できる。失敗が混ざっても成功分は入り、失敗分だけやり直せる。

## Batch 4 — quieter / colorize: 一覧の規律を取り戻す（P2）

/events 一覧と /map 末尾区画の「全面テラコッタ壁」をやめ、DESIGN.md の規則（最も目立つ要素は画面に 1 つ／色の面積は 1 割）に揃える。

- 対象: `src/app/(app)/events/page.tsx`、`src/app/(app)/map/page.tsx`（末尾の区切りなしセクション）、必要なら出来事カードの共通コンポーネント化
- 出来事タイルを /people と同じ surface カードに統一（タイトルは ink、日付は ink-soft、テラコッタは旗アイコンだけ）。primary トーンは「出来事を登録」ボタン 1 つに限定する。
- 日付のコントラストを実測で AA（4.5:1）以上に是正する。
- 併せて /events の並びを人生の時系列（startDate 昇順、精度なし・eraLabel のみは末尾）に変え、地図と一覧の顔を揃える。
- 受け入れ基準: 一覧で最も目立つ要素が 1 つに定まる。タイル内テキストのコントラスト実測が AA を満たす。

## Batch 5: 細部の非対称をそろえる（minor まとめ）

1. **写真削除の失敗を無言にしない**: `PhotoDetailClient` の削除 catch でエラーを表示する（人物削除と同水準に）。
2. **フォームの出口を統一**: `/people/new` に「やめる」を追加し、出来事フォームと型を揃える。撮影日エディタの常時展開と保存ボタンの大きさも、説明エディタ側の段階開示に寄せて統一を検討する。
3. **/home/today スタブの扱いを決める**: 現状は「作成中です」のまま到達可能なだけの画面。推奨は導線のない間はページを隠す（リダイレクト化）。実装するか隠すかは着手時に最終判断。
4. **メタデータ title の修正**: "Memoria|写真から、人生をたどる" → "Memoria | 写真から、人生をたどる"。
5. **検討項目（設計判断つき）**: /map の駅写真タイル 64px は DESIGN.md のタップ領域基準（128px 以上）を下回る。地図のレイアウト制約と相談のうえ拡大可否を決める。/explore の操作ボタンが背の低い横置きタブレットで画面外に出る疑いは、実機相当の高さで確認してから要否を判断する。
